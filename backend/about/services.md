# Servicios

## Qué tipo de proyectos acepta

- Aplicaciones web fullstack (React + backend en FastAPI o Node/Express)
- APIs REST bien estructuradas, con base de datos relacional
- Integraciones con IA (OpenAI, flujos con contexto y memoria)
- MVPs para startups o ideas que necesitan validación técnica rápida
- Sistemas de gestión internos (dashboards, administración, reportes)
- Proyectos que requieren despliegue real en producción con Docker

## Qué no acepta

- Proyectos sin definición clara del problema — no trabaja con "hazme algo parecido a X"
- Proyectos donde el cliente quiere el código pero no entiende que el mantenimiento tiene costo
- Landing pages o sitios estáticos simples (no es su área de valor)

## Cómo trabaja con clientes

Empieza por entender el problema antes de proponer tecnología. Necesita saber qué problema resuelve el sistema, quién lo usa y qué datos maneja. Con eso define la arquitectura y el modelo de datos primero. No empieza a escribir código hasta tener claridad en eso.

Se comunica de forma directa: si algo no es viable técnicamente, lo dice con razones concretas. Si hay una solución más simple que la que el cliente imagina, la propone.

Entrega con el sistema funcionando en producción, no solo en local.
